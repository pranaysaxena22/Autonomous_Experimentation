# Data reader messages

_Generated by `tools/make_ingest_messages.py`. Do not edit by hand: change the wording in `cellpoc/ingest/findings.py` and run the tool again. The health check fails if this file is out of date._

When the reader opens a data file it reports what it found in this form:

> **File › Column:** what happened and what to do

- **Error**: the file cannot be used until the problem is fixed.
- **Warning**: the file was read, but the reader had to assume or repair something. Read these.
- **Note**: information about how the file was read.

Nothing is ever filled in or guessed silently: every repair is listed here. Every message below has a test: a small file made to cause exactly that message. The message shown is the one the test produced (the file name in the tests is `t.csv`).

## Fixed rules the reader applies

These never change and are never hidden: whenever one of them changes what a number or date means, a message above says so.

- **Two-digit years:** a year written with two digits is read as follows: **00 to 69 mean 2000 to 2069, and 70 to 99 mean 1970 to 1999**. Every date read this way is reported (message I71, with an example) and the date column's report says how many were read this way. To avoid the rule, write four-digit years (`yyyy`) in the setup's date format.
- **Day and month are never guessed.** A date is read only in the format the setup states (`dd.mm.yyyy`, `mm/dd/yyyy`, `yyyy-mm-dd`, `mon.yy` ...). With no format stated, only year-month-day is read, and a warning says so (I49).
- **Month names** come from built-in English and Slovenian tables (short and full), or from twelve names in the setup. The computer's own language settings are never used.
- **A date with no day** (such as `nov.18`) becomes the first of that month and is marked month-only; a warning says the order of events inside a month is unknown (I65).
- **A missing value** is an empty cell or text the setup lists under `missing_markers`. Nothing else is assumed, and every marker found is counted (I64). Nothing is ever filled in.
- **A number** is read only when it is clearly one (`12.5`, `12,5` where the decimal mark allows, `1e-3`). Doubtful text is reported and left missing, never turned into a number.
- **Weight check:** a gap of exactly the stated tolerance passes; only a larger gap is flagged, and every row keeps its exact signed gap.
- **Rows are removed only by a stated rule** (missing values with `drop_row`, failed runs, replicate rows combined) and every removal is counted. The quality report opens with a row-accounting block that shows dropped rows and failed runs in capitals with their counts (messages I58 and I84 say the same).
